# UI / UX architecture

The UI redesign supersedes the source-interface preservation requirement (2026-11-26). Preserve business rules, eight roles, quantity semantics and backend object authorization; replace layout/navigation/interactions. Source UI audit is recorded in FIREBASE_DEPENDENCY_AUDIT.md and source maps retained as isolated reference.

App root resolves `/auth/me` and setup status before mounting protected configuration or screens. First run is a three-step form with one-time setup secret; login is username/password. Auth and Config contexts call real SQL APIs. TanStack Query is the sole server-state cache, memory-only, cleared on logout/revocation; no business state or token enters localStorage. Polling uses a commit-ordered event cursor with version conflict responses; hidden tabs pause and focus/reconnect resumes. Browser settings forms retain unsaved edits if a newer server version appears, rather than overwriting drafts.

AppShell uses a grouped expandable sidebar, sticky translucent header/breadcrumb, page search, notification entry and account shortcut. Desktop employee lists are TanStack tables with server search/filter/sort/pagination, optional columns and detail panel. Tablet uses a navigation rail and full-width content; portrait stacks lower-priority panels. Mobile uses role-aware bottom navigation, safe-area padding, explicit additional menu, list cards, bottom-sheet dialogs and full-screen staff forms. Only dashboard/unavailable pages hide mobile chrome on scroll; complex edit pages retain navigation and reserved save space.

shadcn/ui supplies local editable Button/Input/Label/Badge/Table/Dialog primitives built on Radix (one primitive system). App Shell organization refers to Shadcn Admin; free ReUI Radix grid/timeline patterns were reviewed selectively, without copying their full implementation or introducing Base UI. TanStack Table and Query are used directly. Recharts is pinned but unused until reports have real endpoints; no synthetic report masquerades as production. Exact commits, versions and license notices are in THIRD_PARTY_NOTICES.md.

Implemented surfaces: login, setup, role dashboard, employee directory/manage/create/edit/role/lock/reset/revoke, own profile/password, company/workflow/catalog settings, audit view, search/menu/notification unavailable state. Navigation to future modules is explicit unavailable UI, with no Firebase import, local data fallback or placeholder mutation. No production preview datasets or arbitrary Kanban drag/drop transitions.

Future patterns: commercial desktop list/detail; designer controlled queue and local draft editor; assigned printer focused task list with validated ACK/start/complete; finishing per-product queue; warehouse order-aware sibling readiness; logistics dispatch/shipment list/detail; authorized reports with Recharts. Kanban/Timeline/Stepper may visualize states but every transition must use server workflow services. Scheduling/Gantt remains out of Phase 01.

Route anchors are UI navigation only. Server APIs independently authorize every request. Deep links load through SPA fallback, and the service worker caches only the public shell/static assets. Private API responses are NetworkOnly/no-store. Account/physical-device limits: see UI_RESPONSIVE_TEST_REPORT.md and HAWKHOST_DEPLOYMENT.md.
