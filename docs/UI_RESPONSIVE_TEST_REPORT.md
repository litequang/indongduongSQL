# Responsive/browser evidence

Windows / Node 22.22.2 / Playwright 1.62.1 Chromium, built Vite frontend and real Express/MariaDB 11.4.9 test backend on 4173. Browser emulation only; physical iPhone/iPad/Android and Hawk Host remain LOCAL_VALIDATION_REQUIRED. Evidence date: 2026-11-26.

Executed matrix: 360×800, 390×844, 768×1024, 1024×768, 1366×768, 1920×1080, each light and dark. All six completed screens (setup, login, dashboard, users, profile, settings), staff dialog at all 12 combinations, plus mobile menus and additional setup/login captures. 90 PNGs generated in ignored `.local/screenshots`. Screenshots contain synthetic test accounts only.

Final verified functional browser flows: empty-data setup through secret gate, login, staff creation/edit/role change/lock/unlock, second browser-context invalidation, own profile/password, F5 session persistence, logout, settings update/conflict across two contexts, sidebar collapse, navigation search, dialog Escape and Tab, mobile navigation, no horizontal page overflow, and dialog bounding rectangles entirely inside viewport. PWA manifest/service worker installed by production build; CacheStorage inspection found no /api response. No Firebase/Google/R2 requests from the SQL app and no credentials/server DTOs in localStorage.

Failures found during implementation (fixed): malformed HTML username pattern under Chromium's Unicode-v regular expression mode; ambiguous test label selector; mobile dialog retained desktop 50% translation; link-styled primary button inherited the wrong text color; PowerShell ASCII pipe damaged several Vietnamese metadata labels. Visual review caught the dialog defect after the original page-width assertion passed. Explicit x/y/width/height assertions now protect the fix. Full rerun after fixes: 4/4 browser suites PASS (exit 0), with zero unhandled page errors or unexpected serious console errors. Expected 401/403/409 negative-path resource messages are classified separately.

Final release run: 4 PASS / 0 FAIL, exit 0, about 1.4 minutes. axe checked WCAG 2 A/AA and 2.1 AA tags on setup/login plus dashboard/users/profile/settings in light/dark, with zero violations in those scans. A deliberate HTTP 503 injection in a separate service-worker-blocked context verified error/retry UI; retry returned to the real MariaDB API. This is an error-state simulation, never a database substitute. Extra contrast fixes covered workshop initials, setup metadata and decorative flow captions. Settings/profile section links were also tested to retain their page route. Reduced motion is enabled in browser contexts and CSS honors prefers-reduced-motion. Layout review is qualitative; browser simulation cannot verify physical soft keyboard, real safe-area insets, screen reader ergonomics, touch hardware or install/update behavior on actual iOS.

Cross-environment follow-up: Ubuntu CI surfaced contrast-sampler failures on dark dashboard surfaces despite readable screenshot output. Cards now explicitly set their semantic foreground. Accessibility scans use a tall viewport so complete surfaces are rendered; the six-size responsive matrix still tests the original required viewport sizes. Windows was rerun after this change; remote verification is recorded in HANDOFF.md.
