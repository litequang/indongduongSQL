# SQL architecture

One modular Express application, one MariaDB database, one same-origin React/TypeScript/Vite PWA. Hawk Host cPanel/CloudLinux/Passenger is the deployment target; no Redis, Docker requirement, WebSocket or worker daemon. Node 22 is the local/CI target; account-specific availability remains to be verified.

`server/config` validates environment; `server/database` owns a bounded pool and transactions; migrations are explicit CLI work. Routes validate inputs and invoke authorized services/repositories. Audit and change events are committed with the mutation. The browser never chooses its trusted role. Stable UUID user IDs are business identities, with no Firebase compatibility layer.

Passwords: native Node scrypt with random salts; DB holds only password hashes and hashed opaque session tokens. HttpOnly, SameSite=Lax cookies are Secure in production. Mutations require configured Origin and session-bound CSRF header; setup/login require Origin too. Roles/active state are resolved on every request and revalidated inside mutation transactions. Locking/password/role changes revoke sessions immediately. Developer-only first-run secret is supplied out of band, consumed by locked persistent system state, never bundled or logged.

Core schema: roles/users/sessions/settings/setting_options/audit_logs/system_state/schema_migrations/change_events/auth_rate_limits. No business seed. DATABASE_SCHEMA.md describes implemented Phase 02A–C relations and planned private storage. JSON is limited to bounded structures such as import candidates, recipient selection and audit context.

Migrations: ordered immutable files, checksums, MariaDB GET_LOCK, durable running/applied/failed state and statement checkpoint. MariaDB DDL implicitly commits: no false atomic rollback promise. A failed/incomplete migration blocks automatic continuation until an operator inspects partial schema. Successfully applied reruns are no-ops; edited checksums are rejected.

Incremental synchronization: monotonic sequence allocated under system_state row lock before any domain write, retained until commit, avoiding auto-increment commit-order gaps. Events include entity ID/version and deletion tombstone. Bounded cursor pages, role scope and optimistic version preconditions prevent lost updates; visible polling 4 seconds and focus/reconnect refresh, background paused. Unauthorized payloads never enter a global feed.

Frontend: shadcn/ui design tokens and Radix Dialog primitives, TanStack Query in-memory server state, TanStack Table controlled pagination/search/sort/filter. No persistence plugin or production demo mode. Only completed modules mount; unfinished modules are explicit empty/unavailable states. The entire original graph is moved under legacy/firebase and excluded from production compilation/bundling. No Firebase or old JSON-store route executes.

Phase 03 private storage uses backend-only R2 configuration and separate primary/backup buckets per environment. Five-minute owner-scoped SQL tickets precede authenticated same-origin binary upload; the server fully decodes and normalizes JPEG/PNG/WebP before activation, up to 5 MiB and 16 million pixels. At most two uploads are processed concurrently. Authorized no-store downloads proxy verified bytes and recheck current session/object authority after I/O. This replaces the proposed public-facing signed URLs, so credentials, bucket names, bearer URLs and CORS never enter the browser. Conditional object writes prevent overwrite after lost responses. R2 outage has no provider/local filesystem fallback. Test-only dependency injection uses an isolated filesystem transport, never a production fallback. Sharp's native runtime must be verified on the hosting account.

Registry references on immutable design versions and production print images are real foreign keys after migration 007. Unattached uploads remain owner private; official production attachments are immutable and follow current printer assignment. Only unreferenced images can be deleted; a Developer may clean ten unreferenced images older than one day per call. Historical references survive. Explicit device attachment drafts use account/target/slot-scoped IndexedDB for selected File blobs only; SQL/API data and credentials remain memory-only. Logout or confirmed session expiration clears device drafts. Offline F5 requires reconnection/authentication before recovery.

Notifications are recipient rows written with the commit-ordered mutation, paged and marked read only by that recipient. Production notifications obey current draft/assignment scope on every read. Fulfillment alerts contain only the generic workspace ID. Polling pauses in background; optional sound/voice stores UI choices only. Image backup/verify/missing-only restore uses durable SQL jobs of at most 500 registry IDs, one object per request, SHA-256 before/after copying and a separate private backup bucket. Corrupt existing objects are never overwritten. There is no background worker requirement. These image jobs do not replace operator-managed MariaDB database backups.
